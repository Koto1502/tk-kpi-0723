The no-ads .sale packs are still being sold

Evidence only — no revenue modelling. GA4 raw export analytics_538412813 · generated 2026-09-18

On v26.2, v28 and v29 the .sale ad-removal packs are tapped, paid for, and the reward is handed out. 24 completed purchases and 12 in-game reward payouts across those builds, the most recent on 2026-09-18.

It happens for players who installed on that version and for players who installed on an earlier one — the split is in the first table.

1 · Sale-pack activity by app version and install cohort

tapped = purchase_click, the player opening the offer. paid = in_app_purchase, Play billing them. rewarded = earn, the game handing over the entitlement. Any one of them being non-zero means the pack exists on that build; all three means it works end to end.

v27.2 returns no rows at all — that is not evidence of removal. That build only ever reached 7 devices, for a single day; there is no sample to find anything in. Treat v28 and v29 as the releases that matter.

On v28 and v29 the buyers are players who installed on those builds. That is expected rather than surprising: these packs only ever sell in a player's first few days, so a long-standing player would not buy one on any version. v26.2 is where both cohorts show up.

The query that produced the table above — copy and re-run it:

WITH fo AS (                        -- which version did each player install on?
  SELECT user_pseudo_id uid, ANY_VALUE(app_info.version) install_version
  FROM `tiny-knightfall-idle-rpg-game.analytics_538412813.events_intraday_*`
  WHERE event_name = 'first_open' GROUP BY uid
),
sale AS (
  SELECT app_info.version app_version, user_pseudo_id uid, event_name,
         PARSE_DATE('%Y%m%d', event_date) day,
         COALESCE(
           (SELECT value.string_value FROM UNNEST(event_params) WHERE key='product_id'),
           (SELECT value.string_value FROM UNNEST(event_params) WHERE key='position')
         ) sku
  FROM `tiny-knightfall-idle-rpg-game.analytics_538412813.events_intraday_*`
)
SELECT s.app_version,
  CASE WHEN f.install_version IS NULL        THEN 'install version unknown'
       WHEN f.install_version = s.app_version THEN 'installed ON this version'
       ELSE 'installed on an EARLIER version' END cohort,
  COUNTIF(s.event_name='purchase_click')  tapped,
  COUNTIF(s.event_name='in_app_purchase') paid,
  COUNTIF(s.event_name='earn')            rewarded,
  COUNT(DISTINCT s.uid) users,
  MAX(s.day) last_seen
FROM sale s LEFT JOIN fo f ON f.uid = s.uid
WHERE s.sku LIKE '%.sale'
  AND s.app_version IN ('26.2','27.2','28','29')
GROUP BY app_version, cohort
ORDER BY app_version, cohort

Only in_app_purchase carries a USD value; the client-side events (purchase_click, earn, iap_purchase_success, first_purchase) have no money field at all, which is why that column is blank on those rows.

The query that produced the event log above:

WITH fo AS (
  SELECT user_pseudo_id uid, ANY_VALUE(app_info.version) install_version
  FROM `tiny-knightfall-idle-rpg-game.analytics_538412813.events_intraday_*`
  WHERE event_name = 'first_open' GROUP BY uid
)
SELECT FORMAT_TIMESTAMP('%Y-%m-%d %H:%M', TIMESTAMP_MICROS(e.event_timestamp)) ts,
       e.app_info.version app_version,
       IFNULL(f.install_version,'?') install_version,
       e.event_name,
       REPLACE(COALESCE(
         (SELECT value.string_value FROM UNNEST(e.event_params) WHERE key='product_id'),
         (SELECT value.string_value FROM UNNEST(e.event_params) WHERE key='position')
       ),'com.idle.tiny.','') sku,
       ROUND(e.event_value_in_usd,2) usd, e.geo.country country
FROM `tiny-knightfall-idle-rpg-game.analytics_538412813.events_intraday_*` e
LEFT JOIN fo f ON f.uid = e.user_pseudo_id
WHERE e.app_info.version IN ('27.2','28','29')
  AND COALESCE(
    (SELECT value.string_value FROM UNNEST(e.event_params) WHERE key='product_id'),
    (SELECT value.string_value FROM UNNEST(e.event_params) WHERE key='position')
  ) LIKE '%.sale'
ORDER BY ts

4 · The quick version to paste into BigQuery

The two queries above scan the whole export (~2.5 GiB each). This one filters on _TABLE_SUFFIX first, so it prunes to the recent shards and reads about 60 MB — cheap enough to re-run whenever you want to check.

WITH e AS (
  SELECT app_info.version app_version, event_name, user_pseudo_id,
         PARSE_DATE('%Y%m%d', event_date) day,
         COALESCE(
           (SELECT value.string_value FROM UNNEST(event_params) WHERE key='product_id'),
           (SELECT value.string_value FROM UNNEST(event_params) WHERE key='position')
         ) sku
  FROM `tiny-knightfall-idle-rpg-game.analytics_538412813.events_intraday_*`
  WHERE _TABLE_SUFFIX >= '20260916'      -- v28 launch day; widen to look further back
)
SELECT app_version, sku, event_name,
       COUNT(*) events, COUNT(DISTINCT user_pseudo_id) users, MAX(day) last_seen
FROM e
WHERE sku LIKE '%.sale'
GROUP BY app_version, sku, event_name
ORDER BY app_version, sku, event_name

5 · Two things that will bite you when you re-run these

  • app_info.version is a STRING, not a number. IN (28, 29) returns nothing, and so does any SAFE_CAST(app_info.version AS INT64) — because v26 stamps itself 26.2 and casting it yields NULL. Always quote: IN ('28','29').
  • earn stores the SKU in position, not product_id. Filter only on product_id and every reward payout disappears from the results — which is exactly the signal that proves the pack is actually being delivered. Hence the COALESCE in all three queries.
Raw GA4 export only; this export has events_intraday_* shards exclusively, so the current day is always partial. Times are UTC as stored. Regenerate: uv run python dashboard/build_no_ads_report.py.
